# Token 效率开发与实验计划

目标是在真实成果、报告质量、Docker 隔离及核验要求不退步的前提下，减少模型输入和无效往返。评价任务总开销包含失败与修正，不能仅比较成功请求或提示词字符数。

## 基线与第一批范围

开发前已从 `4c3accf19ba5ea0df71cfc027d91a4e0ddc1b9eb` 冻结完整包源码与技能资源。本批保持双 Agent、模型、调用/执行预算和 Docker 镜像，不引入业务专用计算工具。

| 改动 | 预期作用 | 必须保留的边界 |
|---|---|---|
| 单份结构化委派包 | 去除重复 TaskSpec 和二次 JSON 编码 | 原任务、冻结确认与后续新回复不能混淆 |
| 按任务/阶段注入建模策略 | 统计计划接受后不再携带主端建模策略，非建模子任务不加载训练协议 | 计划阶段保留完整默认规则，不用关键词猜测提前删除；建模仍加载拆分、基线、预处理及指标规则 |
| 计划冻结后撤出计划工具 | 减少后续轮次的复杂 schema | 新任务重新开放；无效未接受计划仍可修正 |
| 精简模型回执与成果视图 | 减少重复来源/文件元数据 | 宿主保留完整证据；分页明确表示预览，可按ID读取 |
| 技能按角色路由（首候选实验，未采纳） | 方法指导主要交给代码 Agent | 首批ON组出现退步；未证明因果，保守撤回，正式候选恢复原技能路由 |
| 限制自动携带旧代码 | 最近成功脚本最多一份、32 KiB | 超限明确省略完整代码，从原始快照重算，不发送截断脚本 |
| 数字化请求与缓存计量 | 区分输入、schema、缓存和输出 | 仅保存大小与供应商返回计数，不保存认证信息，不估算未知费用 |

模型视图与宿主记录是不同层次：完整成果、哈希、执行记录、工具调用ID账本、预算与核验逻辑仍保留。模型默认回执以单件4 KiB、整体8 KiB为预览目标；超出时返回最小身份及按ID读取指针，最小身份清单本身不被静默丢弃。完整CSV导出无新增行数限制。

## 对照协议与采纳门槛

第一批采用四个已知公开开发回归任务：过滤分组、按日汇总与指标、真实柱状图、混合特征逻辑回归。每题每版本两次，共16次。Skills OFF与ON使用两个独立固定批次，共32次；两组不合并成单一成功率。此集用于工程筛选，不是未接触留出集或官方排行榜。

每批固定输入、独立判据、模型ID/参数、镜像ID、两份源码快照和评测脚本。版本顺序交错，每次使用新进程和会话。只有显式run命令才调用模型；断点继续不覆盖失败、不重提交已经开始而缺少结果的付费尝试。所有计划试次留在分母，STOP只在试次间停止。

检查实际完整表、指标、图表数据、分类逐行预测/真实标签/拆分/基线及指标复算；状态completed不等于通过。成功还须保存产物并核对原输入哈希。比较任务达成、输入/输出token、调用、修正、耗时与真实技能读取；缓存缺字段记未知，逻辑UTF-8字节不是供应商精确token归因。

候选采纳至少要求：完整离线回归通过；关键能力有真实Docker成功证据；未出现新增错误完成、源修改或权限退步；开发集实际达成不低于基线且token减少。逐题退步必须披露。若发现有风险的改动，保留旧实验，创建新候选与新批次；不能覆盖结果。小样本和模型随机性限制外推，不预先承诺节省比例。

首候选32次已完整保留：OFF两版均8/8、总token下降9.87%；ON基线8/8、候选7/8、总token下降5.43%，未达到采纳门槛。失败为报告交付项漏授权与最终输出格式，真实分类资产最终已通过必需核验。未发现确定性丢字段，也不能据单次失败认定Skill路由因果。第二候选仅保守撤回角色路由，使用全新两批32次重新对照；不覆盖首批，也不把第二批称为首次成功。

不通过换随机种子、删除失败或重复跑到通过来筛选。第二全局候选仍未达门槛：OFF双方8/8且总token下降9.99%，ON基线8/8、候选7/8。因此不全局发布压缩，也不以28.73%的ON token降幅覆盖交付退步。两轮合计64次开发实验全部披露，没有追加第三轮付费试次来筛选成功。

最终集成收窄为按现有Skills配置选择模型视图：Skills关闭使用两轮均独立达标的compact策略，Skills开启恢复基线standard策略；同一套执行、预算、核验和保存代码共用。这是看到开发集结果后的范围收窄，属于事后工程决策，不是原全局候选门槛通过，存在选择偏差，不能称为未接触验证。

集成以隔离进程中的真实Agent图、脚本模型及注入执行器做模型消息/工具schema等价验证：OFF对照冻结v3、ON对照冻结基线。只规范化非语义的运行ID，保留消息顺序、JSON文本与调用关系。固定recipe等价不证明任意输入，也不替代新的留出验证。完整宿主回归及真实Docker/浏览器CI另行验收；不将集成版本虚称为另跑了32次在线实验。单轮只有四题，未覆盖长对话、超宽表、全部报告语义或任意建模任务。

复现工具为 `evaluation/token_efficiency.py`，协议、结果与限制发布到 `evaluation/results/`。原始输入、脚本、模型回答、运行日志与图表留在忽略目录。

## 后续独立实验

1. 连续对话的模型上下文投影：保留完整审计历史，另构建当前任务视图，验证工具消息配对、最新确认、历史引用和新计算证据。首批不裁剪canonical消息。
2. 对核验反馈分类，区分代码错误、约定冲突和报告格式；引入带版本的受控约定修正，不能删用户要求来通过核验。
3. 研究成果齐全后宿主结束子图、轻量单Agent路由和脚本补丁。每项单独比较，保持原容器和证据校验。
4. 再评估角色模型选择及缓存前缀布局。缓存可影响费用但不一定降低计量输入token；不同时更换模型和上下文策略来声称单项效果。

这些机制改变更大，须通过独立回归、开发对照及新的未查看留出任务后再进入正式流程。
