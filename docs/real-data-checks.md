# 真实 CSV 与资料检验

本轮采用一个自主运行入口，不再要求运行 CSV-only 和 CSV-with-PDF 两遍。两种情况仍可分别测试，但是否检索由具体任务决定。

## VS Code 操作

1. 选择项目 `.venv` 解释器，准备支持工具调用的模型配置。
2. 打开 `run_labweaver.py`，点击 Run Python File 或 F5 → LabWeaver: conversation。
3. 输入 CSV 完整路径。
4. 输入可选 TXT/MD/文字型 PDF 完整路径；不提供资料时直接回车，多份路径用分号分隔。
5. 输入自己的任务；多行任务可保存为 UTF-8 TXT，再输入 `@任务TXT完整路径`。
6. Agent 提问时输入回答。完成后输入下一项任务或追问；回车/“退出”结束。

不需要输入 CSV 编码和分隔符。高级显式覆盖可在 TOML 或入口 OVERRIDES 中配置，默认 auto。无法可靠识别时，程序应展示候选解码/分隔符预览，再等待选择。

`run_real_checks.py` 是同一流程的兼容入口。

## 没有资料：CSV 概览

资料路径留空，任务：

> 总结 CSV 的行列规模、字段、逐列缺失情况和实际数值摘要，并说明推断类型的不确定性。

检查：

- 实际执行 `profile_csv`，工具结果行列数与文件一致；
- 没有 `search_materials` 工具执行，也没有伪造资料出处；
- 工具源 SHA-256 与原文件一致；
- 成果 JSON/Markdown 记载实际统计；不必无条件等待确认。

## 有资料：带来源的字段总结

输入 CSV 和相关 PDF，任务：

> 基于这份说明资料解释 CSV 字段含义，结合实际数据总结可以开展的分析，并标明出处。

检查：

- 先执行 CSV 概览，再执行真实搜索；
- 引用 ID 来自 retrieved_chunks，文件名与页码对应 PDF 的实际文本；
- 未命中的字段含义明确记为未知，不凭空补出处；
- 没有将无关建模、论文或 AI 使用规则变为当前概览的前置条件。

仅提供 PDF、任务为明确数值统计时，可以跳过检索。检索状态、决策理由和实际调用应分别记录。无命中与未检索要区分。

## 真实奖牌案例：澄清后计算与追问

在自己的 `summerOly_medal_counts.csv` 上运行，正确格式应为 **1435 行 × 7 列**，列为 Rank、NOC、Gold、Silver、Bronze、Total、Year。

第一项任务：

> 统计获得最多奖牌的前 5 个国家。

若模型确认统计口径，回答：

> 全部年份、按 Total 累计、保留原始 NOC。

全部年份参考答案：

| NOC | Total 累计 |
| --- | ---: |
| United States | 2583 |
| Great Britain | 944 |
| Soviet Union | 907 |
| France | 792 |
| China | 727 |

然后继续追问：

> 改为 2024 年。

2024 年参考答案：

| NOC | Total |
| --- | ---: |
| United States | 126 |
| China | 91 |
| Great Britain | 65 |
| France | 64 |
| Australia | 53 |

应分别核对两次成果，不能以状态成功或“建议按国家分组”代替计算：

- 真正执行 analyze_csv，按一基位置 2（NOC）分组，位置 6（Total）求和；
- 2024 任务对位置 7（Year）筛选；
- 降序取前五且结果恰好五项，保持原始历史国家标签；
- 回复确认后不重复同一工具调用或重复扣预算；
- 新任务重新计算，已有口径仍在会话中；
- JSON、Markdown、独立结果 CSV 的表格一致；
- 运行前后 CSV 与 PDF 哈希不变。

真实源文件和原始日志只在本地保留，不提交 GitHub。程序退出后内存会话结束，JSON 记录不用于恢复。
