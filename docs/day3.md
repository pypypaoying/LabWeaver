# 第三天开发计划：生成带出处的任务方案

状态：**已确认计划，尚未实现**。本轮只更新入口、配置和文档；本文件所列 RAG 功能在下一开发轮实施。建议投入 2–3 小时，优先建立可验证的单 Agent 基线。

## 用户目标

用户提供任务说明、CSV、项目资料。Agent 先读取实际数据，再主动检索资料，输出“任务理解、数据条件、候选分析、资料依据、待确认事项”。

例如“比较不同部门满意度”：结合 CSV、评分要求和变量说明，确认部门分组、满意度含义、候选方法和交付形式；提出缺失信息和冲突要求，标明资料出处。任务从问卷换成实验记录时无需修改工具代码。

终态保持 `awaiting_confirmation`；第三天不执行清洗、建模或绘图。模型自行选择检索查询，属于 [Agentic RAG](https://docs.langchain.com/oss/python/deepagents/retrieval) 的工具检索方式。

## 资料解析与检索

- 只读取用户明确指定的本地资料，支持 UTF-8 TXT、Markdown 和文字型 PDF。
- PDF 用 [pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) 提取文本。扫描件、加密、无法解析或无可用文本的文件给出明确提示；本阶段不加入 OCR。
- 按段落或 PDF 页面切分。片段最多约 800 字符，长段落重叠 100 字符，不跨 PDF 页。
- 每个片段保留文件名、SHA-256、页码或行号、片段 ID 和原文。示例：`[D1-C3]` 对应第一份资料的第三个片段。
- 使用本地 [rank_bm25](https://github.com/dorianbrown/rank_bm25) 检索；中文使用 jieba 分词，保留英文变量名。每次返回最多三个相关片段；无词项匹配则返回空结果，不用零相关片段填满。
- 默认最多十份资料、单文件 5 MiB、总计 20 MiB、单 PDF 一百页。首次在内存建立索引，不接 embedding API 或向量数据库。

文件大小限制并不能单独限制 PDF 解压后的文本或内存。实现时还需对提取文本和片段总量设置明确预算，避免受控输入大小下仍出现无界处理；具体上限写入工具契约和测试。

## Agent 与 Harness 扩展

未来 `run_intake()` 增加可选 `material_paths` 参数；不传资料保留现有流程。新增 `search_materials(query)`，只绑定本次资料，模型不能提供文件路径。

VS Code 入口增加 `MATERIAL_PATHS` 配置；与现有共享配置衔接时，在 TOML 增加 `materials` 路径列表并由该入口读取。CLI intake 增加可重复的 `--material`。这些配置均属于下一轮实现。

预算与顺序：

| 约束 | 上限或规则 |
| --- | --- |
| CSV | 一次 |
| 检索 | 最多两次 |
| 模型 | 最多五次 |
| 图执行步数 | 十六 |
| 检索前提 | 先完成 CSV 概览，再允许检索 |
| 有资料的成功条件 | 至少一次实际检索执行；调用与结果及账本匹配 |

多工具证据按调用 ID 核对全部结果与实际执行账本。非法工具、错误顺序、预算耗尽、缺少必要调用或 ID 不匹配都受控失败。检索执行成功但无命中时，说明资料不足和待补信息；不能编造依据。

任务资料和 CSV 单元格中的指令文本是待分析的数据，不得作为授权更改工具、访问其他文件或突破预算。

## 输出、引用与运行产物

回答固定组织为“任务理解、数据条件、候选分析、资料依据、待确认事项”。只有实际检索返回的片段可以被引用；引用使用 `[D1-C3]`，附文件及行号或页码。伪造引用或错误来源返回失败，无命中时明确资料不足。

JSON 保存资料标识、查询、命中片段与完整工具执行证据；成功运行另外保存 Markdown 任务简报。源文件保持只读，执行前后核对哈希。

引用校验只保证片段实际返回、出处真实且可追溯，**不宣称自动证明回答每句话都受到资料支持**。资料冲突应列为待确认事项，不能静默挑选某一个要求。

## 开发块与验收

| 开发块 | 建议投入 | 可检查产物 |
| --- | --- | --- |
| 资料解析、切分与检索 | 45 分钟 | 真实片段、来源和无匹配结果 |
| Agent 检索与 Harness | 60 分钟 | CSV → 检索 → 带引用回答 |
| 验收、示例与文档 | 45 分钟 | 离线测试、小规模在线结果、任务简报 |

验收清单：

1. 问卷、实验两个项目，更换资料无需修改工具代码；至少五个标注查询，其中一个是资料无答案的问题。
2. 同一 CSV 更换任务资料后，建议和引用随资料变化，数据统计保持一致。
3. TXT、Markdown、文字型 PDF 的来源定位正确；空资料、扫描件、加密、解析失败和超限受控处理。
4. 多工具调用 ID 配对、调用预算、检索顺序、伪造引用、资料中的指令文本均有失败或约束验证。
5. 离线模型走真实工具流程且阻断网络；在线分别记录 CSV 概览与资料检索的实际执行、终态和失败原因。
6. VS Code 直接运行可产出 Markdown 简报，输入文件哈希保持不变。

2–3 小时是建议投入，不是免除验收的截止线。若 PDF 处理或接口兼容问题导致超时，应记录已完成范围与失败原因，保留剩余验收项，不把未通过功能标记完成。

多智能体在后续分析与核验阶段接入；第三天先建立单 Agent RAG 基线，用真实证据衡量检索是否改善任务方案。
