# 数据探索

先确定一行代表什么，再判断字段是标识、分组维度、度量、时间还是自由文本。列名和少量样例只能提供线索；唯一性、类别集合、时间范围和异常数量需要全量证据。`profile_csv` 已有的真实概览可直接解释，用户只问行列数时不扩展成清洗或建模。

## 从概览到必要检查

- 以列映射中的稳定 `cN` 选择原始字段，同名表头仍是不同列。`load_dataset()` 返回原始字符串；`df.attrs['columns']` 是包含 id、position、name 的字典列表。
- 类型转换前留存原始行数、所需字段值与缺失掩码。标识值的前导零、文字 `NA`/`NULL`、数值零不是默认缺失；默认只有空白字符串缺失。不要依赖 pandas 的读取默认值重新解释快照。
- 对需要数值化的非空字段先检查转换失败项。`errors='coerce'` 产生的空值不能未经说明就排除；区分原始缺失、非法文本和非有限数值。处理规则由任务决定。
- 比较完整行重复和业务键重复：同一编号多行可能是多次事件，不能仅因编号重复就删除。只有用户要求去重，或已确认记录粒度和重复规则时，才执行并报告排除数量。
- 日期先检查格式、可解析范围及日/月次序。仅当多种解释会改变结果时澄清；格式明确时直接严格转换，不为无关业务背景反复提问。

## 面向任务的探索

按任务选择检查，而不是对所有列生成庞大报告。质量问题可用“字段、问题、影响范围、处理口径”小表呈现；问题数量来自完整快照，不能把样例频率外推到总体。

若需要检查分布，区分有效数、原始缺失、零值、负值和极端值。偏态不等于数据错误，异常候选也不是自动删除授权。未经资料或用户确认，不给未知字段添加单位、业务阈值或合并类别。

需要计算时交给授权的 `execute_python`，用相应 `emit_table` 或 `emit_metric` 登记事实。解释中区分“观察到的问题”和“可能原因”；后续建议不应变成本次额外交付项。
